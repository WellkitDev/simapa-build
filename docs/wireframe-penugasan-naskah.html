BLUEPRINT — ROLE, TAHAPAN & ATURAN MAIN dasar algoritma backend

Akun rangkap dipisah: "Fitri Admin" ≠ "Fitri Produksi" (permintaan tim). Manager belum ada orangnya → tidak ada approval flow, hanya menerima notifikasi. Akuntansi: read-only status publish/terbit untuk penagihan (fase 2).
2 · Tahapan (state machine)
Artikel: Menunggu → Pembuatan* → Editing → Revisi (opsional, bisa berulang, siklus dihitung) → Submit → LoA → Publish → Arsip
Buku: Menunggu → Pembuatan* → Editing → Layout → Proofreading → ISBN → Cetak → Terbit → Arsip
* Pembuatan hanya untuk order dengan jasa penulisan (SLA 7 hari kerja). Order dengan naskah dari klien: lompat langsung ke Editing saat file masuk. Buku kolaborasi: tahap Pembuatan + Editing berjalan PER BAB (tiap bab punya author, pelaksana, status, file, riwayat sendiri); tahap Layout → Terbit berjalan level buku dan baru terbuka setelah semua bab Selesai; status buku = roll-up bab paling belakang. Pemetaan bab→author wajib sebelum bab bisa didistribusikan ("Author belum dipetakan" ditandai kuning, tidak disembunyikan). Buku mandiri: satu kesatuan, tanpa pecahan bab.
3 · Aturan Algoritma Inti
  1. Gerbang antrian: naskah masuk antrian saat DP terverifikasi. Tanpa DP tidak tampil di papan.
  2. Upload = maju otomatis: upload naskah oleh pelaksana pada tahap Pembuatan otomatis memajukan status ke Editing + notifikasi ke PJ. Ini satu-satunya perpindahan otomatis.
  3. Maju manual oleh admin: satu tombol "Selesaikan tahap → X". Tidak ada dropdown semua-tahap. Catatan opsional saat maju.
  4. Koreksi = jalur terpisah: mundur/lompat lewat tombol "Koreksi", catatan wajib, tercatat sebagai koreksi di riwayat.
  5. Grup judul transparan: aksi tahap berlaku serempak untuk semua order sejudul; UI selalu menampilkan "berlaku untuk N order" + drill-down.
  6. Tanpa approval: perpindahan langsung jalan; notifikasi ke PJ + superadmin; publish/terbit → notifikasi marketing.
  7. SLA & keterlambatan: Pembuatan 7 hari kerja. Lewat SLA/target = merah + wajib isi alasan (internal/eksternal, dropdown baku).
  8. Arsip, bukan hilang: publish/terbit → konfirmasi → pindah ke tab Arsip yang bisa dicari. Tidak ada auto-hilang 30 hari.
  9. Final terkunci kecuali superadmin dengan catatan wajib; semua koreksi terlihat di riwayat.
  10. Audit total: setiap distribusi, claim, oper, maju, koreksi, ubah target/prioritas, upload, batal → satu baris riwayat (siapa · kapan · dari → ke · alasan).
  11. Identitas = kode order di semua layar; judul sebagai pendamping; buku: + nomor bab & author bab.
  12. Bahasa manusia: tanpa istilah "editor"/"aging"/"tracker". Label: "PJ", "Pelaksana", "sudah X hari di tahap ini".
